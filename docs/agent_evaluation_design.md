# Agent Evaluation 初步设计（未实现）

## 1. 边界

本轮只交付设计与初始候选案例，**没有 Agent 评分 Runner、拒答率或幻觉率结果**。
检索层的 Recall/MRR/NDCG 不等于 Agent 分析质量；拿到参考文档不代表正确理解了告警。
不改现有 Agent、输出 Schema、生产提示词或工具执行逻辑。

现有接入点为 `InvestigationService.investigate(alert, alert_pool)`，输出包含 alert、risk、
knowledge、analysis。`SecurityAnalysis` 目前只有 attack_type/confidence/evidence/recommendations；
尚无结构化的 claim 类型和逐条引用，不能假装来源约束已经被自动强制执行。

## 2. 四类陈述必须分开

| 类别 | 合法来源 | 不允许的升级 |
| --- | --- | --- |
| observed_event | 输入告警及实际返回的工具观测，绑定事件时间/资产/账户 | 从文档推断不存在的登录成功、文件落地、横移或损失 |
| reference_knowledge | 冻结 MITRE/NIST/本地安全指南，附 document/block/chunk 引用 | 当成当前告警已经发生对应攻击的证据 |
| supported_inference | 明确列出依赖的 observed_event/reference_knowledge，并给出不确定性 | 将“可能”“建议调查”写成已证实事件 |
| unverified_hypothesis | 后续验证方向及缺失数据 | 捏造查询结果、私有密钥、具体账户或已执行处置 |

本初稿的事件都是**明确标记的合成案例**；不是项目真实生产事件资料。

## 3. 六个评价维度

| 维度 | 评分建议（待领域审核） | 需要保存的证据 |
| --- | --- | --- |
| Alert Understanding | 0 错误/关键漏读，1 部分正确，2 正确识别对象、时间和观测范围 | 输入字段与归纳对应关系 |
| Evidence Grounding | 支持的可核查 claim / 全部可核查 claim；单列来源缺失率 | claim 文本、来源类别、引用、是否真的支持 |
| Hallucination | 无来源或与观测矛盾的事件事实数/可核查事件陈述数 | 账户、IOC、时间、登录结果、已执行动作等逐项核对 |
| Risk Assessment | 0 无依据，1 有依据但尺度欠妥，2 风险与事实/不确定性一致 | 依据、影响范围、建议验证项；不把 confidence 当风险等级 |
| Response Quality | 0 无法执行或危险，1 部分可执行，2 有优先级/对象/验证与回滚条件 | 建议与已执行动作分离，生产封禁/隔离需要审批 |
| Abstention | 证据不足时明确缺什么、不可确认什么；有充分证据时不过度拒答 | 可答/部分可答/不可答标签、缺失数据、输出原文 |

不使用一个模糊总分掩盖严重幻觉。编造真实账户、私有密钥、已执行工具结果等列为
单独严重错误；阈值和人工一致性校准后才决定是否设硬门禁。自动规则不能可靠判断
所有语义支持关系，初期应人工逐条核查，双人抽样并保留分歧和裁决理由。

## 4. 分开测试“生成”和“端到端”

1. **固定证据生成组**：相同告警、工具响应和冻结检索记录，只比较 Agent/提示词。
2. **端到端组**：相同告警与工具数据，从真实检索开始；把检索漏召回与生成错误分开归因。
3. **知识缺口/反事实组**：只有一般知识、相似 IOC、空工具结果、错误时间/资产的资料，
   检查是否错误当成实际事件。不可答题的检索结果非空，不直接算作 Agent 幻觉。
4. 测试模式隔离工具：固定只读观测，不执行真实封禁、隔离、凭据重置或其他外部写操作。

## 6. 初始案例

初稿含八个场景：仅登录失败、跨账户失败、SQL 可疑参数、参考账户知识误当事件事实、
无指定日期事件记录、相似 IOC 不等于同一事件、处置建议不等于已执行、工具无结果。
每例单独列 observed_event、reference_knowledge、允许推断、未验证假设、禁止结论与缺口。
这些是未来人工评价所需输入，**不是已经跑通的 Agent 自动测试**。
